    Create electron/main/database.ts implementing the following specifications exactly:

    ---
    IMPORTS:
    - `import { DatabaseSync } from 'node:sqlite'`
    - `import { app } from 'electron'`
    - `import { join } from 'node:path'`
    - `import { statSync } from 'node:fs'`

    ---
    MODULE-LEVEL VARIABLES (all private, not exported):
    - `let db: DatabaseSync | undefined` — the database instance, starts undefined
    - `let checkpointTimer: ReturnType<typeof setInterval> | null = null` — 5-min checkpoint interval
    - `let walMonitorTimer: ReturnType<typeof setInterval> | null = null` — 1-min WAL size monitor
    - Constants: `const DB_FILENAME = 'wallhaven-data.db'`, `const CHECKPOINT_INTERVAL_MS = 5 * 60 * 1000`, `const WAL_MONITOR_INTERVAL_MS = 60 * 1000`, `const WAL_SIZE_THRESHOLD_BYTES = 10 * 1024 * 1024`
    - Const: `const DB_PATH = join(app.getPath('userData'), DB_FILENAME)` — computed once at module level (does NOT open the database; just computes the path string)

    ---
    FUNCTION: `getDatabase(): DatabaseSync`
    - Guard: `if (!db)` — FIRST check if db is already initialized
    - Inside guard:
      1. `db = new DatabaseSync(DB_PATH, { enableForeignKeyConstraints: true, timeout: 5000 })` — per "Specific Ideas" in CONTEXT.md
      2. Call `initializeSchema()`
      3. Call `startPeriodicCheckpoint()` — starts the 5-min checkpoint interval
      4. Call `startWalMonitor()` — starts the 1-min WAL size monitor
    - Return `db`
    - IMPORTANT: This is the ONLY place where `new DatabaseSync(...)` is called. The database must NEVER be created at module import level.

    ---
    FUNCTION: `initializeSchema(): void` (private, not exported)
    - Call `db!.exec(...)` with multiple SQL statements separated by semicolons:
      1. `PRAGMA journal_mode = WAL;` — enable WAL mode (per D-01)
      2. `PRAGMA foreign_keys = ON;` — redundant safety with enableForeignKeyConstraints (per PITFALLS.md Pitfall 10 prevention)
      3. `CREATE TABLE IF NOT EXISTS settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);`
      4. `CREATE TABLE IF NOT EXISTS search_params (id INTEGER PRIMARY KEY CHECK (id = 1), value TEXT);`
      5. `CREATE TABLE IF NOT EXISTS download_history (id INTEGER PRIMARY KEY AUTOINCREMENT, wallpaper_id TEXT, url TEXT, filename TEXT, file_path TEXT, file_size INTEGER, thumbnail_path TEXT, resolution TEXT, data TEXT NOT NULL, created_at TEXT DEFAULT (datetime('now')));`
      6. `CREATE TABLE IF NOT EXISTS collections (id TEXT PRIMARY KEY, name TEXT NOT NULL, is_default INTEGER NOT NULL DEFAULT 0, sort_order INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL, updated_at TEXT NOT NULL);`
      7. `CREATE TABLE IF NOT EXISTS favorites (collection_id TEXT NOT NULL, wallpaper_id TEXT NOT NULL, wallpaper_data TEXT NOT NULL, added_at TEXT NOT NULL, PRIMARY KEY (collection_id, wallpaper_id), FOREIGN KEY (collection_id) REFERENCES collections(id) ON DELETE CASCADE);`
      8. `CREATE INDEX IF NOT EXISTS idx_favorites_wallpaper ON favorites(wallpaper_id);`
      9. `CREATE INDEX IF NOT EXISTS idx_download_history_created ON download_history(created_at DESC);`

    ---
    FUNCTION: `closeDatabase(): void`
    - IF checkpointTimer is not null: `clearInterval(checkpointTimer)`, set to null
    - IF walMonitorTimer is not null: `clearInterval(walMonitorTimer)`, set to null
    - IF db: try `db.exec('PRAGMA wal_checkpoint(TRUNCATE)')` (final compact checkpoint, catch any error silently), then `db.close()`, then set `db = undefined`
    - Must be safe to call multiple times (idempotent) and safe to call when db was never initialized (no-op)

    ---
    FUNCTION: `withTransaction<T>(fn: () => T): T`
    - `const database = getDatabase()` — ensures database is initialized
    - `database.exec('BEGIN IMMEDIATE')` — use IMMEDIATE to prevent SQLITE_BUSY from concurrent writes (per D-07 and Claude's Discretion)
    - Try block: call `const result = fn()`, then `database.exec('COMMIT')`, return result
    - Catch block: `database.exec('ROLLBACK')`, then `throw error` (propagates original exception per D-07)

    ---
    FUNCTION: `startPeriodicCheckpoint(): void` (private, not exported)
    - `checkpointTimer = setInterval(() => { ... }, CHECKPOINT_INTERVAL_MS).unref()`
    - Inside the interval callback:
      - Try: `getDatabase().exec('PRAGMA wal_checkpoint(PASSIVE)')` — per Claude's Discretion (PASSIVE is non-blocking)
      - Catch: try `getDatabase().exec('PRAGMA wal_checkpoint(TRUNCATE)')` as fallback — catch any error silently
    - Use `.unref()` so the timer does not prevent process exit

    ---
    FUNCTION: `startWalMonitor(): void` (private, not exported)
    - `walMonitorTimer = setInterval(() => { ... }, WAL_MONITOR_INTERVAL_MS).unref()`
    - Inside the interval callback:
      - Try: `const walPath = join(app.getPath('userData'), 'wallhaven-data.db-wal'); const stat = statSync(walPath); if (stat.size > WAL_SIZE_THRESHOLD_BYTES) { console.warn('[SQLite] WAL file is ' + stat.size + ' bytes — checkpointing'); getDatabase().exec('PRAGMA wal_checkpoint(TRUNCATE)'); }`
      - Catch: WAL file doesn't exist yet (no writes have happened) — do nothing

    ---
    EXPORTS (three exported functions using `export function` syntax):
    - `export function getDatabase(): DatabaseSync { ... }` — with body as described above
    - `export function closeDatabase(): void { ... }` — with body as described above
    - `export function withTransaction<T>(fn: () => T): T { ... }` — with body as described above
    - Do NOT export initializeSchema, startPeriodicCheckpoint, startWalMonitor, db, checkpointTimer, or walMonitorTimer

<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Main process code -> SQLite database file | All SQL queries originate from controlled main process code, never from renderer. Renderer accesses data via typed IPC channels. |
| Database file on disk | SQLite file stored at app.getPath('userData') which is user-private on all platforms. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-02 | {T} | SQL queries in database.ts | mitigate | All user-originated data enters via parameterized prepared statements (? placeholders). The initializeSchema() uses static SQL only (no string interpolation). withTransaction() wraps writes atomically. |
| T-41-03 | {T} | DatabaseSync constructor | mitigate | allowExtension defaults to false (not set in options). No SQLite extensions can be loaded. |
| T-41-04 | {I} | WAL file after crash | mitigate | Periodic WAL checkpoint (5-min PASSIVE) limits replay length on next open. closeDatabase() runs TRUNCATE checkpoint for clean shutdown. |
| T-41-05 | {I} | Database file path | accept | Stored in app.getPath('userData') which has correct OS-level permissions. Same location as current wallhaven-data.json. |
| T-41-06 | {E} | WAL checkpoint star-vation | mitigate | Dual protection: periodic 5-min PASSIVE checkpoint (non-blocking) + 1-min WAL size monitor with auto-checkpoint at 10MB. Timers use .unref() to not block process exit. |
</threat_model>
