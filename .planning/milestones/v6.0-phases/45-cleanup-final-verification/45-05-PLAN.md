# Plan 45-05: Delete store.ts and electron-store Dependency

## Objective

删除 `electron/main/store.ts` 和 `src/utils/store.ts`，从 `package.json` 移除 `electron-store` 依赖，清理相关导入。

## Context

### Task 2: Remove store Import from migration.ts

<read_first>
- electron/main/migration.ts
</read_first>

<action>
修改 `electron/main/migration.ts`：

删除第 16 行的导入：
```typescript
import { store } from './store'
```

注意：migration.ts 内部使用 `store.get()` 读取数据。由于迁移已完成（幂等守卫 `_migrated_from_store`），这些代码在运行时不会执行。但为了代码完整性，需要移除对已删除文件的导入。

该导入被以下代码使用（第 93-96 行）：
```typescript
const appSettings: unknown = store.get('appSettings')
const queryParams: unknown = store.get('wallpaperQueryParams')
const downloadHistoryList: unknown = store.get('downloadFinishedList')
const favoritesData: unknown = store.get('favoritesData')
```

**重要：** 由于迁移代码仅在未迁移时执行，而所有用户已完成迁移，这些代码路径不会被触发。删除 store.ts 后，需要将 `store.get()` 调用替换为直接返回 null（因为迁移守卫会阻止执行）。

替换方案：
```typescript
// Migration has already run for all users — these store.get() calls are never reached.
// Store import removed as part of electron-store cleanup.
const appSettings: unknown = null
const queryParams: unknown = null
const downloadHistoryList: unknown = null
const favoritesData: unknown = null
```

或者，更安全的做法是保留迁移逻辑但注释掉 store 导入，添加说明注释。

实际上，根据 RESEARCH.md 的分析，迁移脚本的幂等守卫 `_migrated_from_store` 会阻止重复迁移。因此删除 store 后，迁移代码将无法运行。最佳做法是：

**保留迁移代码逻辑完整性，但将 store.get() 替换为会抛出错误的函数或 null 返回。**

由于迁移守卫在 Step 1 就会返回，这些代码永远不会执行。可以安全地将 store.get 替换为占位符。
</action>

<acceptance_criteria>
- `grep -n "from './store'" electron/main/migration.ts` 返回空
- `grep -n "import.*store" electron/main/migration.ts` 返回空或仅显示其他 store 相关导入
- 迁移代码在 store 不存在时不会崩溃（由于幂等守卫）
</acceptance_criteria>
