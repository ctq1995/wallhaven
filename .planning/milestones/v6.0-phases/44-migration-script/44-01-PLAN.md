<objective>
Create the one-time migration script `electron/main/migration.ts` that reads all 4 data domains from electron-store and imports them into SQLite in a single atomic transaction.

Purpose: Bridge the legacy electron-store data into the new SQLite storage backend, completing the data layer migration started in Phases 41-43. The migration is idempotent (guarded by _migrated_from_store), transactional (all-or-nothing via withTransaction()), and creates a cold backup before any writes.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| electron-store file -> migration.ts | Untrusted input from JSON file may contain malicious strings intended for SQL injection. Electron-store data was written by the app itself, but backup/restore could introduce manipulated data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-01 | Tampering | SQL INSERT statements | mitigate | All INSERTs use parameterized `?` placeholders via prepared statements. No string concatenation anywhere in migration.ts. Electron-store data is serialized JSON — even if manipulated, `?` binding prevents injection. |
| T-44-02 | Information Disclosure | Backup file (.bak) | accept | Backup file created at same path as original (`app.getPath('userData')`), with same filesystem permissions. No elevation of exposure risk. |
| T-44-03 | Denial of Service | Disk space exhaustion | accept | Backup copies the existing file. If the file is maliciously large, the copy will also be large. One-time operation, same disk usage as original. |
</threat_model>
