  <action>
    Modify the `store-clear` IPC handler in `electron/main/ipc/handlers/store.handler.ts` to exclude the `_migrated_from_store` key when deleting from the settings table.

    **The fix (single line change on line 175):**
    Change:
    ```typescript
    getDatabase().exec('DELETE FROM settings')
    ```
    To:
    ```typescript
    getDatabase().exec("DELETE FROM settings WHERE key != '_migrated_from_store'")
    ```

    **Rationale (per Research Pitfall 1 / PITFALLS.md):**
    Without this fix, `store-clear` deletes ALL settings rows including `_migrated_from_store`. On next app startup, the idempotency check finds no flag and re-runs the migration, re-importing old electron-store data over the intentionally cleared state. This is a data-safety regression.

    The `_migrated_from_store` flag persists in the settings table even after the app data is cleared, preventing re-migration. The flag's value is '1' — a sentinel that means "migration completed" with no user-facing significance.

    **Do NOT modify any other handler or code in this file.** The `store-get`, `store-set`, `store-delete` handlers, `keyToTable()`, imports, and all other code remain unchanged.

    **Do NOT modify the comment on line 180:** `// D-07: _migrated_from_store flag is managed by migration script (Phase 44), not DB` — this comment is now accurate: the migration script manages the flag, and store-clear no longer interferes.
