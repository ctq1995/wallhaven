Existing database schema (in electron/main/database.ts):

```sql
CREATE TABLE IF NOT EXISTS collections (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  is_default INTEGER NOT NULL DEFAULT 0,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS favorites (
  collection_id TEXT NOT NULL,
  wallpaper_id TEXT NOT NULL,
  wallpaper_data TEXT NOT NULL,
  added_at TEXT NOT NULL,
  PRIMARY KEY (collection_id, wallpaper_id),
  FOREIGN KEY (collection_id) REFERENCES collections(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_favorites_wallpaper ON favorites(wallpaper_id);
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer -> Main process (IPC) | All 11 favorites IPC channel params are untrusted input from renderer |
| Main process -> SQLite | SQL execution of parameterized queries (safe with prepared statements) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-01 | Tampering | favorites.handler.ts all handlers | mitigate | All SQL uses parameterized queries via `db.prepare('...').run(?, ?, ...)` -- no string interpolation anywhere |
| T-43-02 | Spoofing | favorites-add / favorites-move | mitigate | Foreign key constraint `FOREIGN KEY (collection_id) REFERENCES collections(id) ON DELETE CASCADE` enforces referential integrity; handler pre-checks collection existence with `SELECT 1` |
| T-43-03 | Information Disclosure | favorites-is-favorite | accept | Boolean response about whether a wallpaperId exists in favorites. No PII, no sensitive data leak possible. |
| T-43-04 | Denial of Service | favorites-delete-collection | mitigate | Handler rejects delete if `is_default === 1`; CASCADE delete is intentional by design |
| T-43-05 | Elevation of Privilege | ipcMain.handle registration | accept | All 11 channels are registered in main process only. Preload exposes only invoke methods (no send). VALID_INVOKE_CHANNELS whitelist prevents unauthorized channel access. |
</threat_model>
